# AC130 呼叫与镜头接管

HellForge 0.4 / SDK16 / build25480438，Vix已安装版本的修复案例。
2026-11-28用户在最后一轮计时、锁定与HUD交付后整体反馈良好；此前已明确确认AC130恢复工作。
没有独立测量用户最后一轮的精确接管秒数或联机行为，不把总体认可扩展为全部验证。

## 呼叫变成电磁打击

日志出现`register_entity(.../ac130_call_strike): too many definitions`。
独立载荷注册失败后，原稿的回退路径保留了原版电磁轨道炮载荷和5秒呼叫。
用add_entity及私有逐字段编辑绕过定义块数量限制，不提高底层实体容量；
再失败时禁用该战备并记录原因，不能静默退回一个完全不同且有伤害的战备。
呼叫占位弹用私有零伤害记录，不带撞击或超时爆炸。

SDK16的HfStratagemEvent.thrower是玩家实体，与潜兵avatar entity不同。
新增的thrower==avatar检查曾直接取消炮艇start；HF_ON_STRATAGEM本身已经在投掷者机器触发，
不需要混用这两种身份过滤。普通玩家、角色、unit、网络ID、句柄应分清。

## 计时只保留一个来源

用户随后反馈约53秒，但当时本地日志的两次接受呼叫到ACTIVE为30.051和30.002秒。
证据不足以确定额外时间来自哪里；任务呼叫倍率是线索，不写成确认根因。

最终占位载荷call_in_time=0，只负责触发。原生Shared.phase_started_ms记录GetTickCount64，
接管由30秒阶段计时控制；Lua炮艇位置、倒计时读取同一原生阶段与起点。
取消Lua“飞机已到”回报作为接管前置，避免画面回调失败导致玩法永远等待。
保留60秒操控和退出镜头生命周期，记录实际阶段耗时便于区分调用、飞行与接管。

降低地面潜兵侦测、伤害保护与炮艇目标逻辑分开管理。低侦测不等于清空所有已缓存仇恨，
不能为消除地面仇恨破坏呼叫载荷、角色识别或镜头阶段。
