# HellForge 0.4 注册容量扩展

2026-11-28记录。适用于 HellForge `0.4.0-beta (d8a8b46)`、SDK 16、引擎 `0.1.47.0`、游戏构建 `25480438`。本例保留全部已启用战备包，没有升级到0.5。补丁已编译、通过针对性离线检查并部署；尚未启动游戏验证，也没有用户实战确认。

## 从日志区分容量耗尽和未加载

本例中维克斯包的AC130先注册为类型197，后续战备消失。该包日志依次出现以下拒绝信息。

| 日志片段 | 实际限制 | 排查方向 |
| --- | --- | --- |
| `mods added 48 stratagems already` | 全部模组共用48个新增战备名额 | 检查 `STR_MAX_NEW` 和每次注册返回值。 |
| `register_entity: too many definitions` | `FIELD_MAX_DEFS=64` 的实体定义缓存 | 不要误改成另一个512项武器注册表。 |
| `mods added 64 new projectile types already` | 全部模组共用64个新增弹丸名额 | 检查 `PRJ_MAX_NEW` 及弹丸使用者。 |

`FIELD_MAX_DEFS` 还用于独立的行为定义缓存，两个缓存分别计数。`REG_MAX_WEAPONS=512` 本次保持不变。实体定义拒绝在安装BFV之前的日志中已出现，不能因为最近安装了BFV就把战备丢失归因于它。

加载顺序只会改变哪个包先耗尽名额。用户要保留全部包时，停用或重排包不能完成这个目标。

## 本次容量与边界

| 项目 | 原值 | 本次值 | 约束 |
| --- | --- | --- | --- |
| 新增战备 `STR_MAX_NEW` | 48 | 96 | 原版类型空间150，加起来246，最高类型245。 |
| 战备文本 `REG_STRATAGEM_TEXTS` | 144 | 288 | 每项预留3条文本。 |
| 新增弹丸 `PRJ_MAX_NEW` | 64 | 128 | 原版351，加起来479，最高类型478。 |
| 实体定义、行为定义 `FIELD_MAX_DEFS` | 各64 | 各256 | 保留满额拒绝逻辑，各自计数。 |

战备编号仍使用原来的8位网络字段，弹丸编号仍为9位。保留 `STR_VANILLA + STR_MAX_NEW <= 256` 静态断言，并补上 `PRJ_VANILLA + PRJ_MAX_NEW <= 512` 断言。96和128是本次选择的容量，不是已经证明可以继续任意放大的数值；256个定义也不是游戏运行时实体数量的上限。

## 为什么不能只改宏

原版配装菜单只给150个候选项留出了局部空间。旧48项新增上限依赖可用原版候选数较少；提高注册上限后，必须同步扩大记录区、指针区和函数栈空间。仅改枚举边界可能先显示出全部战备，再在打开菜单时破坏栈。

本次配套改动如下，具体指令、原始字节和写入逻辑见附带补丁。

| 位置 | 必须一起处理的内容 |
| --- | --- |
| `stratagems.c` | 容量、移动表布局、原有表引用及边界修补、菜单初始化和调用参数。 |
| `capacity_picker.h` | 6处栈帧指令、异常展开数据、8处固定数组访问保护、重载计数保护。 |
| `registry.c` | 战备文本容量与战备数量同步。 |
| `projectiles.c` | 新增弹丸容量及原网络位宽断言。 |
| `fields.c` | 实体定义和行为定义缓存同步扩大。 |
| `live_content.c` | 更新 `StratagemRaise` 调用，传入移动后的表。 |
| `hellforge_modloader.c` | 打印本地容量补丁标记，便于确认实际加载的版本。 |

菜单布局按候选数 `n` 计算，每条候选记录20字节，每个指针8字节。

```text
pointers = align16(0x50 + 20*n)
cookie   = pointers + 8*n
frame    = cookie + 0x10
```

6处栈帧指令RVA为 `0x18D8728`、`0x18D873F`、`0x18D8AC8`、`0x18D8AFD`、`0x18D8D63`、`0x18D8D73`；异常展开元数据位于 `0x257FC5C`。扩大函数栈时，要同时调整保存寄存器、栈分配和安全cookie对应的展开信息，不能只修改函数开头的分配量。

配装对象还保留固定150项的选择数组。对类型大于等于150的读取返回0，写入跳过，避免新增战备把数组后面的成员当成选择项。原有新增战备行不写等级包的处理也要保留。新增类型的读写边界保护与菜单扩容是两件事，缺一不可。

重载列表时，原版会重写已加载数量。移动表增加 `STR_LENGTH_AT` 保存数量下限，`STR_ROWS_AT` 随之移动；计数写入处 `0x11F2230` 加保护，避免重载后新增战备再次消失。首次安装与热更新调用要使用同一份表布局。

以上RVA只适用于所列游戏构建。安装前校对全部原指令和异常展开字节，不匹配就拒绝该路径，不能跳过保护硬写。

## 可复用源码补丁

补丁在 [assets/hellforge04-capacity/loader-capacity.patch](../assets/hellforge04-capacity/loader-capacity.patch)，基线为上游 `SkyeShade/HellForge` 提交 `d8a8b46ea830d0a3b8811199180563a803a79bbb`。在干净的该提交源码根目录执行，替换示例中的补丁绝对路径。

```powershell
git checkout --detach d8a8b46ea830d0a3b8811199180563a803a79bbb
git apply --check 'C:\path\loader-capacity.patch'
git apply 'C:\path\loader-capacity.patch'
```

不要在含用户改动的源码树中强行切换提交。先单独获取匹配基线，再构建原生 `native/mod-loader/hellforge_modloader.c`；不替换启动器、后端、SDK或MOD DLL。此次本机构建采用Zig的 `x86_64-windows-gnu` 目标、C11、MinHook 1.3.4，编译入口会包含其他加载器源文件；MinHook使用 `buffer.c`、`hook.c`、`trampoline.c` 和 `hde/hde64.c`。

菜单保护参考上游 `a4898611` 对同一游戏构建的实现，做了局部回移。**该参考源码本身是0.5，不能因为文件夹叫 `hellforge04-source` 就拿它整体替换0.4。** 本补丁未引入0.5 SDK或扩大的网络格式。

源码补丁基于HellForge，版权归2026 SkyeShade及HellForge贡献者；本地修改日期为2026-11-28，按GPL-3.0发布，并保留上游附加许可。许可原文随补丁放在同一资源目录。不包含完整上游源码、游戏资源、镜像、DLL、日志或账户配置。

## 部署与回退

游戏退出后，备份 `app/sdk-shims/hellforge_modloader.dll` 和同目录 `build.json`。替换加载器后，只更新 `build.json` 的 `modLoader` 指纹，保留其他字段；指纹取本次实际编译结果，不照抄别人的值。构建和暂存MOD不等于启动游戏。

启动后应能看到 `local 0.4 capacity patch` 诊断行，再检查此前被拒绝的包是否完整注册、配装菜单能否打开。不要把暂存成功或日志中列出MOD数量当成游戏内完整恢复。

回退时，在游戏退出后恢复这两个原文件；注册容量也会回到原值。HellForge更新或修复安装可能覆盖补丁。多人参与者应使用相同加载器和MOD列表，避免旧加载器只接受部分条目；保留网络位宽并不代表已经验证联机兼容。
