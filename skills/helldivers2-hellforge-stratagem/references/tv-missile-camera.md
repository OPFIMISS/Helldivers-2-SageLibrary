# 电视弹摄像头接管与变速

适用 HellForge 0.4 / SDK16 / 游戏构建25480438。2026-11-28用户确认数控火箭筒
能正常进入导弹视角并操控。随后新增的Shift变速通过编译与定向离线检查，尚未实战确认；
联机同步、每种退出分支与性能开销没有分别验收。开发端未启动游戏。

## 职责分离

原生代码负责私有弹丸、飞行、碰撞、伤害与击杀归属；引擎Lua只负责镜头和HUD。
保留原生碰撞弹丸，不用纯显示单位冒充可命中的导弹。每发接管分配非零generation，
清除旧发射姿态，等弹体发布真实位置且age至少0.04秒后才移动镜头。
数控火箭筒本例2/10、2600伤害、5穿爆炸、2.4米范围、拆毁40；这些是本武器规格，
不应硬套到其他摄像头武器。

## 镜头必须在渲染前重新应用

在原始update返回后应用一次弹体镜头，并在调用原始render之前再应用一次。
普通角色相机会在update之后覆盖姿态，只改update会表现为“代码正常，仍看不到导弹视角”。
原始函数参数及多个返回值均保留；嵌套世界更新可能再次进入包装器，用重入标记挡住递归。

update与render分别维护心跳，超过350毫秒时分别检查包装是否被其他脚本替换并恢复。
共用一个心跳会被仍在运行的update掩盖render丢失。已有包装用弱键表识别，避免重复套自己。

镜头发现优先查core/units/camera，每250毫秒更新一次单位与镜头槽位列表。
自定义相机回退每批最多查询128个单位的镜头，但World.units仍会取得完整列表，
不能把这个回退写成整体严格限量或已经测过性能。
每帧根据unit+slot重新调用Unit.camera；相机所属单位仍存活不代表旧Camera句柄有效。

保存选中镜头的局部位置、四元数和FOV，退出时用新取得的句柄恢复。
本例优先选择玩家附近镜头，镜头放在弹体前方1.1米、垂直FOV62度，避免钻进弹体或尾焰。
当前世界已经更换时，不再写入旧世界的相机。多人分屏和多个自定义镜头需要另行限定所有权。

## 确认与输入释放

只有render阶段确实写入有效镜头后才向原生层确认接管。
首次确认最多等待2秒，确认后的心跳容忍750毫秒；都使用墙上时钟，避免游戏暂停时不超时。
输入捕获本身只有250毫秒有效期，持续刷新且仅限游戏在前台时生效。
切出游戏、换武器、操作者变化、弹体结束、主动退出、Lua拒绝或心跳丢失均释放输入。

低级键鼠钩子仅使用已缓存的前台状态、捕获期限及原子增量。
不要在钩子回调同步查询其他窗口线程、设置光标或运行游戏逻辑；鼠标增量来自钩子坐标。
不要为了停住潜兵把原生移动速度写成0或0.01；本实现不冻结移动速度，也不覆盖迷彩加速。
这些属于最终实现的规避措施，不能据此宣称已证明某一项就是历史未响应的根因。

日志分开记录launch queued、missile realized、render confirmed和released原因。
注册成功或单独出现realized不能证明接管成功。本轮日志有多次渲染确认与弹体结束释放，
加上用户实测确认，支持镜头已工作的结论；极近距离命中可能早于首次渲染确认。

## Shift单击变速

每发导弹默认30米/秒，按一次Shift切90米/秒，再按一次切回30。
物理弹丸初速度也设30，避免接管前先以旧速度飞行。
加速120米/秒平方、减速150米/秒平方，每步dt限制到0..0.1秒；HUD显示档位、实际速度和切换键。
自动交接到有效目标后加速到90，手动退出则保留当时档位，不强制突然变速。

键盘钩子记录左右Shift独立的按下边沿，忽略注入输入和系统长按重复。
物理按键状态在非接管期间也跟踪，避免发射前按住Shift触发虚假的首次切换。
释放接管时清空待处理次数，不盲目清空物理按键状态；游戏线程取待处理次数的奇偶来切档。

Lua终端查询的前10个返回值保持不变，第11个追加速度，第12个追加高速布尔值。
保持原子快照桥接，不从游戏线程直接调用Lua。
网络包增加boost字段并改用RTV2魔数，继续验证发送者、武器归属、弹体seed和有限方向向量。
20Hz发送档位与方向，接收端使用同一变速函数；所有玩家必须使用同版，联机效果仍待实测。

## 历史失败与复用范围

| 轮次 | 用户结果与实现变化 |
| --- | --- |
| 初版 | 能进弹体视角，但游戏未响应；没有证据将根因唯一归到移动速度或输入钩子。 |
| 中间修复 | 移除了渲染前应用，用户反馈完全不进入视角。不要把这一版当作可用方案。 |
| 已确认版 | 恢复渲染前应用，独立心跳、实时相机句柄、重入保护及移除移动冻结共同保留。用户确认正常。 |
| 本轮变速 | 只增加速度、Shift边沿与HUD/网络字段，保留已通过的镜头接管流程。仅编译和离线检查通过。 |
