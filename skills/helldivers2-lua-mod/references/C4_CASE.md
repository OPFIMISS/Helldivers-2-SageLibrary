# C4 背包：从屏幕数字到字段所有者

2026-09-25 用户澄清 C4 为手持一枚、背包备弹六枚（UI 1/6）。最初查看 WeaponMagazine、WeaponRounds、BackpackComponent 时，容易误把引爆器记录或另一个资源的映射 index=6 当容量；它们都不是背包六发的证据。

通过资源路径 `content/fac_helldivers/equipment/backpacks/c4_charge_backpack/c4_charge_backpack` 计算种子零 MurmurHash64A `0x2A18F81C44A26771`，在参考版本的 `DepositComponentData` 映射区偏移 688 定位 index 10。该版表长 5488，映射区 928 字节、30 条记录×152 字节，C4 行首偏移 `928+10×152=2448`，对应三个 u32 `6/6/3`。同表弹药背包 `4/4/1`、榴弹背包 `120/120/60`，支持“起始量/上限/补给”候选解释。不要把该偏移套用到结构已变化的版本。

对应 MOD 仅替换 C4 行的前两项（备弹 8/8 或 10/10），第三项 3 不变。MOD 启动时检查当前版 EXE/game.dll、整表 SHA、C4 资源映射和原字段；不吻合则不写入。2026-09-25 用户反馈组合 MOD “效果是有效的”，这是用户侧实战结果，不是本仓库发布的游戏资源或独立日志；未说明选了 8 还是 10，也未逐项核对补给、掉落/拾取与组合包里 EAT 各项。工具查询历史解码文件只能标记为历史证据，不能凭本案例把游戏更新后未核验的值写回去。

工程取舍：耗时主要发生在发现真实组件/所有者，而不是改两处数值。优先基于实际表现选资源、看同类型正对照、版本锁定和一次针对性实测；避免重复全内存扫描和无关测试。
