# 常用字段及证据边界

下列偏移取自已解码并交叉核对的示例版本。SageLibrary 的索引输出始终附原始输入 SHA 和游戏版本状态；游戏更新后必须重新解码或导出，不能仅凭旧布局修改内存。

## DamageSettings（示例记录 76 字节）

记录自 ID 在 +0（u32），普通伤害 +4（i32），耐久伤害 +8（i32），四角度穿甲 +12/+16/+20/+24（u32），拆毁 +28（u32）。示例 ID 206 为普通 450、耐伤 225、穿甲 [4,4,4,0]、拆毁 20；只说明这一条样例，不能自动映射任意枪。Wiki AP3 的“中穿”要结合角度和弹丸到伤害 ID 的运行时绑定，不降级高于 AP3 的值。

## ProjectileSettings（示例记录 272 字节）

弹丸自 ID 在 +0，不保证按 ID 顺序排列。速度 +32（float32），关联伤害 ID +60（u32），impact explosion +144（u32）。伤害 ID 不能当作弹丸或模型的资源 ID，爆炸编号也不能单独证明碰炸机制。可共用弹丸，必要时拆分武器模式。

## DepositComponentData 和 WeaponReloadComponentData

Deposit 案例见 [C4_CASE.md](C4_CASE.md)，其前三项字段解释依赖同类背包对照，不适用于任意类型组件。WeaponReload 示例表有 498×16 字节资源映射、250 条×80 字节记录；+4 为 Ability ID，+56 为 Duration（float32）。Duration=0 表示用 Ability 默认时长，不可做 `0/1.3` 宣称提高换弹速度；最终仍需核对动画状态和可以开火的时间。

## 可靠性顺序

参考字段名 < 旧版本解码记录 < 当前版自 ID/资源绑定/原值 < 实际写入并回读 < 游戏中实测效果。引擎更新后重新校验整表与原值；游戏内脚本须保留失败即停止和回滚路径。SageLibrary 是**查询器**，不修改游戏，也不凭数字自动生成 Lua MOD。
