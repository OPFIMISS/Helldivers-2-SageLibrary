# HellForge 独立装备模块

以已实测的光学迷彩模块为起点，复用“空投装置 → 原生拾取 → 安装身体能力”的路径。
装置从未进入原生背包槽，不是增加第二个背包槽，也不是先装备再把库存清空。
2026-11-26用户确认它可与其他背包同时使用，并确认最终骨骼折射修正效果正常。

## 先确定边界

样例只支持 HellForge 0.4 / SDK16 / 游戏构建25480438、单人任务和每条生命一个迷彩模块。
它证明了独立模块路径可行，没有实现通用多模块注册器、联机同步或外骨骼。
新构建需重新定位原生函数，保留样例的构建与代码签名检查，不复制地址后直接写入。
启动游戏、改已安装MOD和发布文件仍以用户本次授权为准；本案例开发端未启动游戏，实战验收由用户完成。

## 复用入口

- 制作新模块前，读[安装与生命周期](references/installation.md)，确认资源身份、权威、延迟回收和提交顺序。
- 扩展外骨骼、多个模块或联机时，读[扩展边界](references/extensions.md)，区分已实现机制和设计建议。
- 能量要适配断腿慢走或需要可撤销移速加成时，读[实际速度与能量](references/movement-energy.md)。2026-11-28新增代码未实战确认，不能覆盖下方实测快照的验证状态。
- [assets/module-example](assets/module-example)保留实测版本的原创C源码、Lua显示脚本和按键配置，不含DLL、游戏资源、SDK或内存导出。该快照需要自行提供SDK16、对应私有模型/图标/材质和MOD清单，不能单独作为成品安装。
- `src/module_state.h`可单独复用状态事务；`module_pickup.h`依赖`optical_wear.h`提供的原生查询、资源身份与存活函数，不是独立头文件库。
- 骨骼折射与恢复细节见相邻战略配备Skill的[角色折射](../helldivers2-hellforge-stratagem/references/skinned-refraction.md)。新增战备、投送架和资源包注册也由该Skill处理。

## 保留的实现约束

按私有装置资源判定拾取，不拦截所有背包。非本模块调用原样转发manager、wearer、item、slot、drop全部参数；不要按调用者返回地址判断拾取来源，其他MOD的hook chain会改变栈。

先登记安装请求，在后续game-thread tick调用原生实体回收；确认装置消失后才提交能力。不要在交互栈里销毁unit，也不直接改Inventory槽。重复拾取不替换已装模块、不消耗另一个装置。

能力跟随角色生命身份，普通背包切换不改变模块。死亡、离开任务、角色变化或非单人状态清除模块；回收失败不授予能力。被回收装置的handle只作本次生命的逻辑令牌，不再解引用。

显示、AI效果、输入和能量分别管理。只需能力时不必生成额外人体；需要外观挂件时单独绑定已有骨架，不能让未蒙皮的网格混入显示。

## 验收范围

复用后做与改动对应的少量检查：普通背包调用是否原样通过，装置是否只回收一次，确认回收前是否不授予能力，换包是否保留能力，死亡和退出是否清理。随后由获授权的游戏测试确认实际交互与画面。
历史成功不替代新模块的验证，也不要求每次重复全盘哈希或无关回归。
