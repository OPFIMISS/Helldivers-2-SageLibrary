# 扩展到外骨骼与多个模块

本文件是依据已通过迷彩模块提出的设计路线，不是已完成的外骨骼或通用框架。先沿用原生空投拾取和延迟回收，再按新模块真正需要的能力扩展。

## 能直接复用什么

已证明可用的是不占原生背包槽的安装事务、角色生命期状态、独立按键和能量，以及原生C玩法与Lua显示分离。外骨骼可以借这个入口授予能力，但提升负重、移动、减伤或跳跃都需要分别定位真实参数与原生行为，不能只换装置名称就算实现。

| 新需求 | 建议处理 | 当前状态 |
| --- | --- | --- |
| 被动强化模块 | 安装确认后授予能力，移除时撤销自己持有的修改。 | 安装可复用，具体强化未实现。 |
| 可见腿架或机械臂 | 将独立几何绑定原角色既有骨架或原生挂点，保留关节索引和动画。 | 需要新增建模与绑定验证。 |
| 多种模块同时安装 | 一个统一拾取路由按私有资源分发，各模块有自己的实例和清理逻辑。 | 当前只有一个迷彩ModuleState。 |
| 模块替换或主动拆卸 | 先定义替换规则、掉落和能力撤销，再扩展状态事务。 | 当前重复拾取被拒绝。 |
| 联机 | 主机确认安装，向各端同步角色生命身份与模块状态，处理迟加入及死亡。 | 当前明确禁用。 |

## 多模块状态与效果所有权

确定有第二个模块时，再抽象注册表。每个模块可保存稳定模块ID、角色生命身份、实例ID、能量、激活状态和外观挂件；将拾取资源映射到模块定义，不复制一套全局hook去争抢同一个背包入口。

多个模块可能同时修改移动、减伤、目标可见性或材质。用统一计算、引用计数或明确优先级处理同一效果；一个模块关闭时只撤销自己持有的效果，不能把另一个模块的增益也恢复掉。不要每帧把全局数据重写成固定值来维持能力。

多个主动模块需要独立按键或明确切换方式。原迷彩背包与独立模块虽然可以共同安装在MOD列表中，同一角色同时激活两套迷彩仍可能争抢H键、材质和恢复记录；尚未实现跨MOD效果所有权。

## 外骨骼的外观边界

沿用潜兵动画的机械外骨骼属于身体附件；带独立移动、驾驶与武器系统的机甲是另一套实体系统，不能从模块安装成功推断机甲已可实现。

有外观时，保留原版关节名称、父子关系、权重与inverse bind。不要生成一个静止人体骨架，再把它贴在正在运动的潜兵上。头盔、衣服、武器和背包可能由多个挂接unit构成，网格缓存应按实际挂接关系维护。
离线模型编码与原骨架保留流程见相邻的[0.4资源Skill](../../helldivers2-hellforge04-assets/SKILL.md)。

透明效果必须使用支持蒙皮的顶点程序。普通静态折射材质曾把人体绘制成十字姿态；排除碰撞或阴影材质并不能修复缺少骨骼权重输入的问题。详细修正见战略配备Skill的角色折射参考。

## 先做的最小原型

保留现有迷彩成品，给新模块独立资源名和状态。先让一次空投拾取安装一个可撤销、与背包无关的单一能力，再加入外观；需要多个模块时再处理共存规则。不要把现有工作版的slot6改成另一个未知槽号来试探“第二背包”。

只验证这次新能力会影响的行为；当前单人成功不外推到联机、死亡掉落、存档或跨任务保留。
