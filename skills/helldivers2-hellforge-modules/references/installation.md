# 不占背包槽的安装路径

## 已通过的行为

2026-11-26，HellForge 0.4 / SDK16 / 构建25480438。用户确认光学迷彩模块拾取后能与普通背包共用，最终修正后的折射视觉也通过。模块仍限单人；未独立验证联机、精确帧时间或所有背包种类。

| 层 | 实现 |
| --- | --- |
| 空投 | 独立战备160秒冷却，用原生HellpodRack生成并升起私有装置。直接把装备当投送架会卡进地里。 |
| 拾取 | 借用原生背包交互，只在安装函数入口识别本模块资源。 |
| 安装 | 跳过本装置的原生Inventory安装，申请延迟回收。原背包不被卸下。 |
| 能力 | 确认回收完成后保存角色与逻辑令牌，输入、能量和AI效果读取模块状态。 |
| 显示 | 安装后的空投装置不继续绘制，角色效果由Lua管理；不额外创建人体或背包。 |

## 当前构建的原生证据

以下均为`game.dll`相对地址，只能随构建与函数签名一起使用。

| 位置 | 已研究含义 |
| --- | --- |
| `+0x97DA94` | 原生背包交互分支设置slot6。 |
| `+0x97DAAB` | 调用`+0x9AE030`，返回后跳`+0x97D63A`继续交互完成与清理。 |
| `+0x9AE030` | 安装入口，参数为manager、wearer、item、slot、drop。 |
| `+0x9AE1F8` / `+0x9AE215` | 分别卸旧装备与装新装备；模块路径在函数入口前拦截，因此两步都不执行。 |
| `+0xFDC310` | 原生实体回收入口，排队清理或发送原生销毁消息；不是`World.destroy_unit`。 |
| `+0x97F2B2` | 原交互尾部在部分条件下也会调用同一回收入口。 |

原安装分支不包含其他装备路径上的`+0xBF0950`装备通知。不要凭另一个装备分支的外观相似性补发通知。

## 状态事务

```text
空闲
  → module_begin(wearer, pickup)
等待回收
  → 后续tick调用原生retire一次，requested=true
等待确认
  → 装置unit消失或不再存活
已安装
  → module_commit保存wearer和token，清理pending
死亡 / 换角色 / 离开任务 / 非单人
  → module_clear
```

`module_begin`拒绝零身份、已安装和已有待处理请求；`module_commit`要求同一请求者且已发起回收。5秒未确认则取消。若原交互已经回收装置，tick可直接确认，不重复回收。

当前`token`沿用已回收装置的handle，仅作本次角色生命中的能量身份。不把它传给unit API、不用它查模型，也不将它视作永久唯一ID。未来多模块或存档系统应另建模块实例ID。

## 拾取过滤与共存

先从实体描述取实际资源。不是本模块时，调用下一层hook并原样传递全部五个参数；不要改普通背包的返回、丢弃标记或Inventory。

本模块要求slot6、当前本地活角色、任务中、物品权威成立，且会话角色为SOLO、人数不超过1。任一条件不符时不安装本装置。`coop: shared`清单字段本身不代表已实现同步；运行时单人检查才是当前边界。

按资源身份识别调用，不依赖调用者返回地址。共享hook chain可能增加中间栈层，返回地址过滤会让本应拦截的安装漏回原生背包路径。

## 为什么不用清空背包槽

原生装备维护不止一个槽值，还涉及卸装、交互、挂接、网络和其他管理器。先装上再把slot清成0会留下不一致状态，也可能丢掉原背包。当前路径不进入原生安装，因此无需事后修复库存。

回收放在交互调用栈退完之后，交给原生实体管理器处理；不能用Lua直接删unit冒充完整实体销毁。

## 继承补给包时的坑

私有克隆且`own_all=1`仍保留原行为。将Deposit容量、初始和补充量设0；当前构建还需在确认152字节私有记录`+0x24`原值为2629后，替换成`game.dll+0x3483C5C`给出的no-action ID。原生`+0xA4385A`读取指令`8B 48 24`是该字段依据。SDK16没有命名此字段，不能杜撰字段枚举。

源码在失败时禁用模块战备，不继续把继承补给动作的装置当成独立模块使用。

## 源码阅读顺序

`module_state.h` → `module_pickup.h` → `optical_wear.h` → `optical_module.c`。输入和AI效果在`optical_effect.h`，能量在`cloak_energy.h`，原生Lua桥在`optical_hud.h`，显示在`optical_view.lua`。

样例只提供原创实现，不上传提取的模型、材质、GPU程序、游戏DLL镜像或SDK。资源名与构建锁定信息可供合法本机重建，不能替代用户自行拥有的游戏文件。
